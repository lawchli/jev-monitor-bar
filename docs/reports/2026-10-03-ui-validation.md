## 极限正常窗口搜索实测

临时基准 `/tmp/jev-ui-window-bench-20261003.ts`，运行 `node --import tsx /tmp/jev-ui-window-bench-20261003.ts`，退出码 0。两份数据均为同一 run 的 20,000 条协议有效事件；逐条 `validateEvent` 后经过生产 `sanitizeEvent`，合成 `password=…` 已被替换。按 EventStore 相同的 `Buffer.byteLength(JSON.stringify(event))` 口径累计，严格不超过 32 MiB。每份窗口分别使用 ASCII、混合中文/全角字符的摘要；不是只构造 500 条渲染行。

## 审查发现与边界

**U1（中，冻结版本性能风险）：** 非空查询对整个已加载范围重新 `JSON.stringify`、NFKC 归一和匹配；即使只渲染 500 行，也不能降低 20,000 行/32 MiB 搜索的扫描量。`useDeferredValue` 改变渲染优先级，不将这段同步函数放入线程，也不保证单次扫描可中断。上述 206–255 ms 中位数属于明显的主线程长任务。

源码还显示 `ExpandedView` 每次重渲染会重新 `.filter()` 创建事件数组、重新创建 `laterAttemptKeys` 集合；`useMonitor` 每秒更新 `now`。因此非空搜索在没有新事件时也可能重新执行，浏览极限历史窗口时不应宣称低 CPU 或无卡顿。

U1 已反馈 root 与独立集成审查 agent。此报告创建时源码与交付包保持冻结，尚未擅自修改功能。建议在重新打包前协调有界缓存或分块计算，并同时保住 run/回放切换隔离与脱敏边界；若保留当前实现，必须明确记录极限历史搜索卡顿风险。该风险不能因功能测试通过而标为已修。

布局方面：紧凑模式仍保留四行核心信息；依据 CSS 字号/行高/间距核算，正常行内容约 76 px，平台提示与存储告警同时存在时压缩纵向空白。展开区重新安排选择器、状态摘要、页签、卡片和时间线留白，提供深浅色、可见焦点与减弱动画设置。**这里只做源码核算，不是 Chromium 像素测量，也不是 Windows 200%/混合 DPI 实测。** 当前环境原生 Electron 被 OS 沙箱阻止，不能把布局与窗口行为写成已实测通过。

## 后续修复与复验：U1 及历史重试筛选

上面的冻结版本性能数据作为修复前基线保留。root 明确要求修复，不接受只记录限制；因此重新开放 renderer 范围，并将旧包标记为已过时，最终制品必须从再次冻结后的源码重新构建。

### 已完成修复

- 实际 `TimelineTab` 改用 `searchTimelineItemsAsync`，约 6 ms CPU 预算切片后通过 `setTimeout(0)` 让出事件循环；不启用 CSP 已禁止的 Worker，不新增依赖、文件读取或网络请求。
- 以不可变脱敏事件对象为 WeakMap 键，缓存已经序列化/归一的搜索文本。后续关键词不再逐条重新 JSON 序列化；弱键不会阻止离开引用范围的事件被 GC。缓存字符串、事件对象、React 模型和聚合状态不计入后端 32 MiB 序列化窗口上限，不能声称渲染进程总 heap 只有 32 MiB。
- `ExpandedView` 与 `ReplayView` 稳定 memo 事件数组和 run 重试提示，时钟每秒更新不再凭空重建输入数组/重启搜索；“全部”类别复用已构建的时间线模型。
- 每次关键词、类别或源变化均取消旧搜索；切 run、回最新清缓存或卸载时通过 AbortController/来源身份隔离过期结果。搜索中明确显示状态，不显示旧关键词的匹配数量或伪造“无匹配”；空关键词即时恢复列表，不等待冷扫描完成。
- 独立审查另外复现历史重试漏筛：真实 Store 中先写同一动作 first/retry 两次，再写 501 个新动作，旧两项从最多 500 项的 attempt 聚合表中移除，但两条历史事件仍在已加载范围。原实现用 run 提示完全覆盖本地历史证据，漏掉 cursor 2。现将两类重试证据取并集，并识别上游实际提供的 `action.selected.payload.retry > 0`；不会把不同 action 的首个尝试误标为重试。

### 新增自动化回归

`timeline-search.test.ts` 从 4 项增至 8 项，新增跨切片/缓存语义一致性、开始前与 yield 后取消、真实 503 条事件/500 项聚合上限的历史重试回归，以及显式 retry 字段。

`timeline-search-ui.test.ts` 从 5 项增至 8 项，新增快速关键词切换、6,000 条事件上的增量快照/Escape/切 run 过期结果隔离，以及空 run 提示下加载历史 first 后识别 retry、快捷键卸载与 Escape 作用范围。原无匹配分页、失败重试、500 行渲染上限、键盘页签测试保留，等待异步搜索完成后断言真实 DOM。

当前两个新增套件 16/16；加旧时间线 4、expanded model 12、compact model 13，合计 45 项。类型、renderer/test 格式与 diff 检查通过。最终全仓测试、制品哈希和独立复审结论由 root 的交付记录集中登记。

冷搜索并没有消除所有总 CPU 成本，而是避免将约 230–240 ms 搜索工作放进同一个不可让出的同步调用；界面可以先显示“正在搜索”并响应取消。热查询通过复用已脱敏的规范化文本降低重复 CPU。6 ms 是尽力而为预算，单个事件处理、GC 或调度可能超过预算；此轮最大 10.41 ms，不应承诺硬实时上界。时间线模型首次构建本身仍是同步的，前述约 42–48 ms 构模数据不等于被分块搜索消除。

独立审查者另外用其自己的 20,000 条/32 MiB 窗口复测冷/热一致性和 yield 后取消，确认功能正确；其 ASCII 冷片存在一次约 19.76 ms 长片，也说明预算不是硬上界。独立完整数据和最终交叉审查见 `2026-10-03-final-crosscheck.md`。

U1 的“单次全窗口重新序列化且同步阻塞”路径已被实际 UI 分块搜索替换，历史重试漏筛也已修复并真实复现后验证。源码再次冻结；这两项不再以“接受限制”交付。原生 Chromium/Windows DPI 仍未在本轮环境实测，布局边界说明不变。
